# گزارش وضعیت فنی نسخه 0.2.3

## تغییرات این مرحله
1. تأیید/رد رزرو: تغییر وضعیت و ثبت Audit Log در تراکنش واحد و با شرط `status = PENDING`.
2. پیامک: فقط پس از Commit موفق تراکنش تصمیم رزرو فراخوانی می‌شود.
3. تکمیل رزرو: شرط `status = APPROVED` و `endsAt <= now` در UPDATE دیتابیس اعمال می‌شود؛ Audit Log اتمیک است.
4. لغو رزرو: شرط وضعیت قابل لغو و `startsAt > now` در UPDATE دیتابیس اعمال می‌شود؛ Audit Log اتمیک است.
5. نسخه workspaceها و Expo app.json به 0.2.3 هماهنگ شد.
6. GitHub Actions CI افزوده شد تا در یک محیط تمیز، PostgreSQL 16، Prisma، typecheck، build و آزمون‌ها را اجرا کند.

## نتایج قابل بازتولید در محیط فعلی
- `node --test tests/static-integrity.test.mjs`: **20 از 20 آزمون موفق**.
- بررسی نحوی 8 فایل TypeScript/TSX با TypeScript transpileModule: بدون خطای نحوی.
- 12 فایل JSON: معتبر.
- 3 اسکریپت Shell: بررسی نحوی موفق.
- نسخه تمام workspaceها و اپ موبایل: هماهنگ روی 0.2.3.
- فایل CI از نظر ساختار و وجود مراحل ضروری بررسی شد.
- آرشیو ZIP: سالم.

## محدودیت‌های تأیید
در این محیط pnpm، Docker و PostgreSQL در دسترس نیستند و دسترسی به npm Registry نیز وجود ندارد. بنابراین Build وابسته به پکیج‌ها، typecheck کامل، Prisma validate/generate واقعی، migration واقعی، تست HTTP/E2E، آزمون بار، تست نفوذ مستقل و ساخت APK/AAB/IPA هنوز اجرا نشده‌اند.

CI اضافه‌شده این کنترل‌ها را در محیط GitHub Actions پس از قرارگیری سورس در مخزن Git اجرا می‌کند؛ نتیجه CI هنوز از این محیط قابل مشاهده نیست.

## وضعیت انتشار
**Source Stage: آماده بررسی و ادامه توسعه. Production: تأییدنشده.**

پیامک واقعی، ورود اطلاعات کارکنان واقعی و اتصال به دیتابیس عملیاتی همچنان غیرفعال/ممنوع تا زمان تأییدهای رسمی هستند.
