# چک‌لیست راه‌اندازی عملیاتی PSK Meeting

این چک‌لیست باید توسط مالک سامانه، فناوری اطلاعات و مسئول امنیت تکمیل و امضا شود. عبور از Build به‌تنهایی به معنای آمادگی Production نیست.

## A. زیرساخت و دسترسی

- [ ] سرور Production و محیط Stage از هم جدا هستند.
- [ ] DNS، TLS معتبر، تمدید خودکار گواهی و Reverse Proxy پیکربندی شده‌اند.
- [ ] PostgreSQL فقط در شبکه خصوصی در دسترس است؛ پورت DB عمومی نیست.
- [ ] رمزهای POSTGRES_PASSWORD، JWT_SECRET، QR_HMAC_SECRET و OTP_HMAC_SECRET مستقل و تصادفی‌اند.
- [ ] هیچ کلید یا رمز در Git، Docker image، گزارش یا فایل ZIP نهایی وجود ندارد.
- [ ] محدودیت نرخ و محدودیت حجم درخواست در Reverse Proxy نیز فعال است.
- [ ] فضای ذخیره‌سازی، CPU، RAM و دیسک پایش می‌شوند.

## B. پایگاه داده و بازیابی

- [ ] Migrationها روی دیتابیس خالی اجرا شده‌اند.
- [ ] Migration روی کپی داده Stage اجرا و نتیجه تطبیق داده شده است.
- [ ] Constraint عدم هم‌پوشانی با دو درخواست هم‌زمان واقعی آزمایش شده است.
- [ ] پشتیبان رمزگذاری‌شده روزانه و پیش از هر تغییر مهم گرفته می‌شود.
- [ ] بازیابی پشتیبان در محیط جداگانه با موفقیت آزمایش شده است.
- [ ] RPO و RTO مورد قبول سازمان ثبت شده‌اند.
- [ ] هیچ Seed آزمایشی یا حساب پیش‌فرض در دیتابیس عملیاتی باقی نمانده است.

## C. امنیت هویت و مجوزها

- [ ] ورود ناموفق، قفل ۱۵ دقیقه‌ای پس از پنج تلاش و rate limit آزمایش شده‌اند.
- [ ] OTP با کد اشتباه، انقضا، پنج تلاش، درخواست مجدد و مصرف دوباره آزمایش شده است.
- [ ] تغییر رمز، reset رمز، غیرفعال‌سازی کاربر و تغییر نقش/دسترسی نشست قبلی را باطل می‌کنند.
- [ ] تمام APIها با کاربر EMPLOYEE، DEPT_MANAGER، ROOM_ADMIN و SUPER_ADMIN آزموده شده‌اند.
- [ ] تست IDOR و دسترسی بین شعب تهران و کاشان انجام شده است.
- [ ] محدودیت واحد سازمانی برای مدیر واحد بررسی شده است.
- [ ] عدم افشای اطلاعات جلسه محرمانه، موبایل، ایمیل و داده کاربران در گزارش‌ها تأیید شده است.
- [ ] تست XSS، CSRF، CORS، CSP، SQL/ORM abuse و ورودی‌های مخرب انجام شده است.

## D. رزرو و خدمات

- [ ] رزروهای هم‌پوشان حتی در درخواست هم‌زمان ثبت نمی‌شوند.
- [ ] ظرفیت اتاق کنترل می‌شود.
- [ ] انتقال وضعیت فقط طبق گردش‌کار مجاز انجام می‌شود.
- [ ] لغو پس از شروع جلسه مجاز نیست.
- [ ] مدیر واحد فقط رزروهای واحد خودش را می‌بیند و تصمیم می‌گیرد.
- [ ] QR جعلی، منقضی، خارج از بازه جلسه و اسکن تکراری رد می‌شود.
- [ ] درخواست خدمات بین سایت‌ها و واحدها ایزوله است.

## E. کارکنان و Excel

- [ ] فایل کارکنان از منبع رسمی منابع انسانی و مالک داده تأیید شده است.
- [ ] کد پرسنلی، ایمیل، موبایل و شعب با سامانه مرجع تطبیق داده شده‌اند.
- [ ] رکوردهای آزمایشی، غیرفعال، تکراری و حساب‌های سرویس جدا شده‌اند.
- [ ] ابتدا Preview انجام و خطاها رفع شده‌اند.
- [ ] تعداد ردیف‌های آماده با تعداد مورد تأیید مالک داده برابر است.
- [ ] Commit توسط مدیر مجاز انجام شده و گزارش و خروجی رمزهای موقت در محل امن نگهداری شده‌اند.
- [ ] رمز موقت کاربران در اولین ورود تغییر داده می‌شود.

## F. پیامک و اعلان

- [ ] SMS_ENABLED در محیط توسعه و تست false است.
- [ ] Kavenegar با حساب و خط ارسال سازمانی و کلید امن پیکربندی شده است.
- [ ] ارسال آزمایشی فقط پس از تأیید سازمان و با شماره‌های تست مجاز انجام شده است.
- [ ] خطای سرویس پیامک موجب برگشت یا قفل شدن رزرو و حساب کاربر نمی‌شود.
- [ ] محتوای پیامک اطلاعات محرمانه جلسه را افشا نمی‌کند.

## G. تست، آموزش و پذیرش

- [ ] Build، typecheck و تست‌های خودکار CI سبز هستند.
- [ ] تست بار برای ۴۰۰ کاربر و بار اوج انجام شده است.
- [ ] تست مرورگرهای سازمانی، موبایل Android و iOS انجام شده است.
- [ ] دسترس‌پذیری، RTL، نمایشگر کوچک و خطاهای شبکه بررسی شده‌اند.
- [ ] راهنمای کاربر، مدیر اتاق و مدیر کل آماده شده است.
- [ ] مسئول پاسخ‌گویی، مسیر ثبت رخداد و برنامه بازگشت به نسخه قبل مشخص شده است.
- [ ] تأیید کتبی مالک کسب‌وکار، IT و امنیت برای Go-Live اخذ شده است.

## تصمیم نهایی

تا زمان تکمیل تمام کنترل‌های حیاتی و امضای مسئولان، وضعیت سامانه **Pilot / Stage** باقی می‌ماند و نباید مرجع رسمی رزرو یا اطلاعات پرسنلی سازمان باشد.


## اصلاحات سخت‌سازی نسخه 0.2.1

- [ ] در محیط Production، `QR_HMAC_SECRET` حداقل ۳۲ نویسه تصادفی و مستقل باشد.
- [ ] اگر `SMS_ENABLED=true` است، `OTP_HMAC_SECRET` حداقل ۳۲ نویسه و `KAVENEGAR_API_KEY` معتبر تنظیم شده باشد؛ برنامه در صورت فقدان این موارد باید از شروع خودداری کند.
- [ ] پایان دوره قفل ورود، شمارنده تلاش ناموفق را به پنجره جدید بازنشانی کند.
- [ ] خروج کاربر از وب و موبایل endpoint خروج را فراخوانی و نشست را در سرور باطل کند؛ در قطع شبکه خروج محلی همچنان انجام شود.
- [ ] مدیر اتاق فقط حساب کارکنان شعب مجاز خود را مدیریت کند؛ ایجاد نقش‌های مدیریتی فقط در اختیار مدیر کل باشد.
- [ ] گزارش بهره‌برداری، رزروهایی را که با بازه گزارش هم‌پوشانی دارند محاسبه و مدت را به مرزهای بازه محدود کند.
- [ ] Service Worker فقط cacheهای دارای پیشوند `psk-meeting-` را پاک‌سازی کند و cacheهای سایر برنامه‌های همان origin را دست‌نخورده بگذارد.
