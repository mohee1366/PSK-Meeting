# برنامه فوری ۴۸ ساعته — PSK Meeting

## خروجی مورد نیاز
1. پنل ورود کارکنان از Excel از طریق وب‌اپ مدیریت.
2. فایل APK اندروید با پروفایل Preview و buildType=apk.
3. حفظ کنترل‌های امنیتی؛ بدون ورود آزمایشی به دیتابیس واقعی.

## ورود اطلاعات کارکنان
- مدیر کل (`SUPER_ADMIN`) یا مدیر اتاق مجاز (`ROOM_ADMIN`) وارد نسخه وب شود.
- از منوی «کاربران و دسترسی‌ها» وارد بخش «ورود گروهی کارکنان از Excel» شود.
- قالب `PSK_Employee_Import_Template.xlsx` را دریافت کند.
- ستون‌های الزامی: `employeeCode`, `fullName`, `siteCodes`.
- ستون‌های اختیاری: `mobile`, `email`, `department`.
- کد شعبه تهران: `PSK-THR`.
- کد شعبه کاشان: `PSK-KSH`.
- هر دو شعبه: `PSK-THR,PSK-KSH`.
- کد پرسنلی و موبایل را در Excel از نوع Text نگه دارید.
- حداکثر ۵۰۰ ردیف داده و ۴ مگابایت در هر بار.
- ابتدا Preview را اجرا کنید. تا وقتی حتی یک خطا وجود داشته باشد، Commit در دسترس نیست.
- پس از اصلاح خطاها، Preview تازه بگیرید و سپس Commit را اجرا کنید.
- همه حساب‌های واردشده با نقش `EMPLOYEE` ایجاد می‌شوند و در اولین ورود باید رمز را عوض کنند.
- فایل رمزهای موقت فقط یک بار نمایش داده می‌شود؛ آن را در فضای محدود و امن نگهداری و پس از تحویل امن پاک کنید.
- از ارسال فایل رمزهای موقت در گروه‌های عمومی یا پیام‌رسان‌های غیرمجاز خودداری شود.

## ساخت APK
پروفایل `preview` در `apps/mobile/eas.json` برای خروجی APK پیکربندی شده است.
ساخت نهایی با EAS Build انجام می‌شود، چون Android SDK/Gradle و حساب EAS در محیط توسعه حاضر در دسترس نیستند.

برای اجرای workflow:
1. سورس را در مخزن خصوصی GitHub قرار دهید.
2. در GitHub Repository Secrets دو مقدار مجاز و متعلق به سازمان ثبت شوند:
   - `EXPO_TOKEN`: توکن دسترسی EAS متعلق به حساب سازمان.
   - `EXPO_PROJECT_ID`: شناسه پروژه EAS.
3. در Repository Variables مقدار `EXPO_PUBLIC_API_URL` را برابر نشانی عمومی HTTPS سرویس API قرار دهید.
4. از Actions، workflow با نام `Build PSK Meeting Android APK` را با `Run workflow` اجرا کنید.
5. EAS Build باید به پایان برسد و لینک APK در خروجی build ارائه شود.

## چک‌لیست قبل از ورود واقعی کارکنان
- API از اینترنت سازمان و فقط با HTTPS در دسترس باشد.
- PostgreSQL backup گرفته شده و restore آن آزمایش شده باشد.
- seed بنیادین دو شعبه و پنج اتاق اجرا و کنترل شده باشد.
- حساب مدیر کل واقعی از مسیر امن ایجاد شده باشد؛ هیچ حساب پیش‌فرضی در سورس وجود ندارد.
- مدیر کل ابتدا فایل کوچک آزمایشی با ۱ تا ۲ کارمند آزمایشیِ مورد تأیید سازمان را در محیط staging بررسی کند؛ نه در دیتابیس عملیاتی.
- پیامک واقعی تا تأیید اعتبار حساب Kavenegar خاموش بماند.
- سپس فایل کارکنان واقعی از منبع رسمی منابع انسانی گرفته و Preview شود.

## نکته درباره رکوردهای قبلی
عدد حدود ۴۲۰ رکورد قبلی به‌عنوان تعداد قطعی کارکنان فعال فرض نمی‌شود. فایل منابع انسانی باید مرجع اصلی باشد. ورود گروهی فقط کاربر جدید ایجاد می‌کند و رکورد موجود را به‌روزرسانی نمی‌کند.
